# Proposal-1 实现计划：TaskCommander 编排器（Phase 1 — Plan-Execute）

> 对应提案：`docs/proposal/p1-2026-08-04.md`
> 状态：已规划，未实施。日期：2026-08-04

## 背景与决策

提案提出新流水线，核心是引入 **TaskCommander** 作为 plan 级编排器，让 plan→executor→planner 形成显式双向环，为 ReAct / Plan-Execute 多 agent 架构打基础。

**已确认的决策**：
1. Phase 1 只做 Plan-Execute（保留现有 DAG 行为），ReAct 留钩子
2. **TaskCommander 内置归约** —— TaskReducer 被吸收删除
3. **结果走 Commander→Planner** —— StateManager 不再直发 Notify

## 改造后架构（对照提案 7 步）

```
/chat → TaskWrapper ──TaskPreplanned──▶ TaskPlanner（生成 plan，含 Architecture）
        TaskPlanner ──TaskPlanned──▶ TaskCommander（sm.Ingest 上传任务）
        StateManager：DAG cascade + allDone 检测（唯一完成权威）
        StateManager ──TaskPlanDone──▶ TaskCommander（reduce 合成在此做）
        TaskCommander ──TaskPlanCompleted──▶ TaskPlanner（查 planID→Notify，发 PlanResult）
        TaskPlanner ──Notify chan──▶ SSE
```

## 实现步骤（每步独立可编译）

### Step 1 — 数据模型（api/）
- `api/v1/domain/task/task_plan.go`：加 `type AgentArch string` + `ArchPlanExecute`/`ArchReAct` 常量 + `TaskPlan.Architecture` 字段（默认 plan_execute）
- `api/v1/messaging/event/event.go`：加 `TaskPlanned`、`TaskPlanDone`、`TaskPlanCompleted` 三个 EventType
- `api/v1/messaging/taskmsg/task_msg.go`：加共享负载 `TaskPlanResultMsg{PlanID, Result PlanResult}`
- `api/v1/registry/module/module.go`：删 `TaskReducer`，加 `TaskCommander ModuleType = "task_commander"`

### Step 2 — StateManager 去直发（manager.go）
两处 `plan.Notify <-` 改为 `m.publish(APIEvent.TaskPlanDone, TaskPlanResultMsg{...})`：
- `Complete()` 的 `allDone` 分支（约 line 213-216）→ `PlanOK`
- deadline watch（约 line 402-405）→ `PlanTimeout`；且 line 373 的 `plan.Notify == nil` 守卫去掉
- 保留 `allDone` 检测（唯一完成权威），保留 deadline 定时器（唯一定时器）
- 新 import `APITaskmsg`

### Step 3 — TaskCommander 组件（新建）
`internal/task_workflow_layer/task_commander/commander.go`，沿用 sealed-interface + AvailableModule 模式：
- `NewTaskCommander(mm, sm)`，从 mm 解析 pm/tt/pc（同 board/reducer 构造）
- `Start` 三个 watcher：
  - `TaskPlanned`(*TaskPlan) → `onPlanned`：存 `runningPlan` → `sm.Ingest(plan)` → `decideNext`（**ReAct 钩子**，Phase 1 对 plan_execute 为 no-op，react 打 warning 日志）
  - `TaskReady`（`Stage==StageReduce`）→ `reduce`：**从 TaskReducer 原样搬迁**（sm.Plan → tracer 收集 → GetPlanProv 合成 → 截断/降级 → tt.SetOutput → sm.Claim/Start/Complete）
  - `TaskPlanDone`(TaskPlanResultMsg) → `onPlanDone`：用 `runningPlan.finalized` 做 exactly-once 守卫 → 发布 `TaskPlanCompleted` → delete 计划
- 内部状态 `plans map[TaskID]*runningPlan`，mutex 保护

### Step 4 — Planner 改造（planner.go）
- 加 `mu sync.Mutex` + `notifies map[TaskID]chan<-PlanResult`；删 `sm` 字段（及 import）
- `plan()`：生成 plan 后设 `Architecture = ArchPlanExecute`；tracer import 保持**在发布 TaskPlanned 前**（FIFO 保证先于 Commander 的 Ingest）；把 `plan.Notify` 存进 `p.notifies[plan.ID]`；发布 `TaskPlanned`（替换 `sm.Ingest`）
- `Start` 加第三个 watcher `TaskPlanCompleted`：`delete-after-take` 从 notifies 取 chan → 发 `msg.Result`（buffered 1，不阻塞）
- `parse()`/`fallbackPlan()` 里 TaskPlan 字面量设 `Architecture: ArchPlanExecute`（防御性）

### Step 5 — 删 TaskReducer + main.go 装配
- 搬移：`reduce()`/`parentPlanID()`/`textFromResponse()` → commander 包；`reducer_test.go` 的 `TestParentPlanID` → commander_test.go
- 删目录 `internal/task_workflow_layer/task_reducer/`
- `cmd/pc/main.go`：`commander := taskcommander.NewTaskCommander(mm, sm)`；注册/启动/停止替换 reducer；启动顺序 `... planner, commander`；删 `reducer.Stop()`

## 关键设计论证

- **TaskPlanDone 必须由 StateManager 发**：`fallbackPlan` 无 reduce 节点，Commander 无法自检完成；deadline 定时器已在 SM 中，Commander 自建会双重通知
- **Exactly-once 三重防护**：SM 的 `allDone`（Complete 与 deadline 互斥）+ Commander 的 `finalized` 标志 + Planner 的 delete-after-take
- **reduce 节点保留在 planner 追加**：它是 plan 拓扑的一部分（successors/leaves），无需搬到 Commander；Board 已跳过 reduce 节点，Commander 的 TaskReady watcher 是唯一消费者
- **fallback 单节点 plan**：无 reduce 节点，executor 的 `sm.Complete` 直接触发 `allDone` → TaskPlanDone，路径畅通
- **Notify 映射生命周期**：所有终止路径（OK/Timeout）最终发 TaskPlanCompleted，planner 发送后 delete，无泄漏
- **并发 plan**：三张 map 均按 planID 键控 + mutex；planID = `plan-<unixnano>` 无碰撞
